## Known Issues / Blockers

- **#28** (new to the tracked backlog as of this checkpoint) --
  `GET /get/{id}` serves stale SEO meta immediately after a `POST /update`
  write, on `tristate-hvac.com`. `/preview-update` sees the fresh value
  immediately, so the underlying write + `get_post_meta()` path is fine;
  the issue reporter's own follow-up comment found `tristate-hvac.com`
  runs both **LiteSpeed and Varnish** in front of WordPress, and
  `rmb_update_meta()` only busts WordPress's own object cache
  (`wp_cache_delete()` / `clean_post_cache()`) -- it never calls the
  LiteSpeed/Varnish purge logic that `rmb_cache_purge()` (`POST
  /cache/purge`) already has. Likely fix: have write handlers (starting
  with `rmb_update_meta()`) call the same purge routine, or purge just the
  affected URL, on every write. Not yet scoped as a version-bump task.
