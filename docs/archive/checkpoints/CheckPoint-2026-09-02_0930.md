  The user pasted the corrected registry JSON directly; it had a missing

  two already-working sites) until caught and fixed. Live-verified after
  the fix: `rankrocket_sites` lists all three sites, and
  `rankrocket_status` against `endlessenergyfitness` confirms plugin
  v3.14.1, RankMath active, Elementor + Elementor Pro active,
  `wp_version: "7.1"` (real, user-confirmed -- not a bug).
- **Domain-level 301 (non-www -> www) set up and verified for
  `endlessenergyfitness.com`.** Confirmed via source read of
  `includes/class-rrseo-redirects.php` that this plugin's redirect engine
  is path-only (`rr_redirect_normalize_path()` strips scheme/host before
  matching) and architecturally cannot do a domain-level redirect --
  correctly routed the user to cPanel's Domains > Redirects tool instead
  (Permanent 301, source `endlessenergyfitness.com` root, target
  `https://www.endlessenergyfitness.com`, "Do Not Redirect www.", Wild
  Card Redirect checked). Reviewed the user's cPanel screenshot before
  they clicked Add, then verified live via `curl -sIL` with cache-busting
  query strings after: domain root and real static files (e.g.
  `/wp-includes/js/wp-embed.min.js`) get a clean single-hop 301 from the
  new cPanel rule (no WordPress headers); real WP-routed pages (`/about/`,
  virtual `/robots.txt`) get a clean single-hop 301 from WordPress's own
  pre-existing `redirect_canonical()` instead (site's `home`/`siteurl`
  were already set to `www`). Net result for every real URL tested: single
  301 hop, full path+query preserved, correct final 200 on `www`. No
  loops.
- **Diagnosed a non-issue during verification**: an initial test against
  a fictitious path (`/some-page`) returned a 301-to-homepage tagged
  `X-Redirect-By: Rank Math` -- traced this to RankMath's own "redirect
  404s to homepage" feature (the path doesn't exist; origin tagged it
  `HTTP.404`), unrelated to the www/non-www work. Correctly flagged as
  inconclusive and re-tested against real sitemap URLs instead.

## Known Issues / Blockers
- **cPanel domain-redirect rule ordering (not urgent, no user-facing
  impact right now)**: the new cPanel `.htaccess`-level redirect only
  fires at the raw server level for the bare domain root and genuine
  static files. Every WordPress-routed URL is currently caught by
  WordPress's own `redirect_canonical()` first, almost certainly because
  cPanel appended the new rule *after* the `# BEGIN WordPress` block in
  `.htaccess`, so WP's catch-all rewrite-to-`index.php` rule intercepts
  first. Functionally fine today since WordPress's own canonical redirect
  already covers every real page/post route correctly -- but it means the
  domain-level redirect isn't true defense-in-depth yet (e.g. if
  RankMath's canonical handling were ever disabled). Fix would require
  moving the cPanel-added block above the WordPress block in
  `.htaccess`; no SSH/file access to that host from this session to do it
  directly.
