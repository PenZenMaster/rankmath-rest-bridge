1. **Housekeeping: #21 closed, Stage 2 split into #27.** The prior

2. **#27 and #26 scoped without new research forks** -- both were fully
   understood from code built earlier this session, so scoping happened
   directly rather than via parallel research agents. One finding
   resolved a real blocking question from first-time reading of
   Elementor's actual source (not recollection or a live test): Elementor
   hooks `the_content` at **priority 9**
   (`Frontend::THE_CONTENT_FILTER_PRIORITY`), replaces `$content`
   wholesale, and its `remove_content_filters()` only strips three
   hardcoded WordPress core filters (`wpautop`, `shortcode_unautop`,
   `wptexturize`) -- never third-party plugin filters. This meant #26's
   content-emission filter could be built to run at priority 20 with
   certainty, without deploying test code to a live client site. Posted
   to #26 before implementation began.
3. **#27 SHIPPED + CLOSED (v3.13.0)** -- all five items deferred from
   Stage 1 (v3.9.0/v3.9.1):
   - `match_type: regex` -- 200-char cap, nested-quantifier
     (`(x+)+`-shape) rejection, PCRE-validity check. Still checked
     against the WP-core-path blocklist as a literal-match safety net.
   - Cross-domain targets -- absolute `http(s)://` URLs accepted when
     their host is on the `rrseo_redirect_allowed_hosts` filter
     allowlist (global, empty by default). **Bridged into WordPress
     core's own `allowed_redirect_hosts` filter** -- without this,
     `wp_safe_redirect()` would have silently downgraded an
     already-validated external target back to a same-site redirect,
     since those are two separate allowlists by default. Found and fixed
     during implementation, not part of the original scoping writeup.
   - `hit_count`/`last_hit` telemetry -- write-throttled to one options
     write per rule per 60s regardless of actual traffic (skip-if-recent
     approach, per user's choice); deliberately skips the REST-cache
     purge on hit-recording writes specifically, to avoid
     cache-thrashing a popular redirect.
   - Multi-hop loop detection -- chain-walks through other exact-type
     rules (A -> B -> A, up to 10 hops), superseding Stage 1's
     `source === target`-only check.
   - Typed-action engine integration -- `create_redirect`/
     `update_redirect`/`delete_redirect` added to `RR_ACTION_TYPES`,
     wired directly onto the existing `rr_redirect_create/update/delete()`
     pipeline (no reimplementation), full dry-run/execute/rollback +
     drift-detection support.
   - Match precedence with multiple types in play: exact wins outright,
     then longest-matching prefix, then first-matching regex.
   - Admin UI Redirects table gained a Hits column.
   - 42 new tests (379 -> 417).
4. **#26 SHIPPED + CLOSED (v3.14.0)** -- visible FAQ content emission:
   - `POST /faq/{post_id}` gained `position` (`after_content` default /
     `before_content` / `disabled`) and `heading` fields.
   - Rendered into a `<section class="rrseo-faq">` block and
     appended/prepended via a `the_content` filter at priority 20 --
     safely clear of Elementor's priority-9 replacement per the source
     research above.
   - Schema and visible content are always generated from the same
     stored `items`, so they cannot drift apart -- the exact failure
     mode #22 was originally raised to prevent.
   - New `_rrseo_faq_display` meta key, kept separate from the schema
     graph itself (same separation-of-concerns pattern as #23's
     `strip_third_party` config).
   - Guarded to the real front-end Loop (`is_singular()` +
     `in_the_loop()` + `is_main_query()`, skipping feeds) so it never
     fires on widgets, secondary queries, or this plugin's own
     `class-rrseo-observe.php` diagnostic endpoints.
   - **Backward compatible with Stage 1 data** -- an FAQ created before
     v3.14.0 stays schema-only after upgrading; visible emission only
     activates once a display config is explicitly written. Deliberate
     choice to avoid a surprise front-end content change on existing
     sites the moment this version ships.
   - 12 new tests (417 -> 429).
5. Suite grew 379 -> 429 tests (50 new) this half; phpcs clean on every
   commit; both release zips built via the pre-push hook and verified.
